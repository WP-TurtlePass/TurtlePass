# 디지털 투어패스 제안서

2026-09-22 주제 변경에 따른 제안 배경. 구현 범위는 [요구사항](../spec.md), 진행 상태는 [현황](../tasks.md)을 따른다.

## 제안 요지

방문객이 혜택 조건을 한곳에서 이해하고 하나의 디지털 패스로 제시·사용할 수 있는 웹서비스를 제안한다. 구현은 거북섬 배경의 허구 시연 상품 1종으로 진행한다. 가족 체험·해양레저와 실제 제휴·가격은 향후 검토 대상이다. 지역 상권 활성화는 검증할 기대효과다.

## 사용자 흐름과 화면 초안

| 화면 | 역할·핵심 행동 |
|---|---|
| 패스 목록·상세 | 이용자가 포함 혜택·유효기간·추가 비용·예약 조건을 비교 |
| 시연 발급·내 패스 | 시연임을 확인하고 발급, 제시용 정보·잔여 혜택 확인 |
| 가맹점 사용 확인 | 담당자가 패스와 적용 혜택 확인 후 사용 처리, 실패 이유 확인 |
| 사용 내역 | 이용자가 사용 결과 확인, 담당자는 자기 가맹점 기록 조회 |
| 관리자 | 상품·가맹점·혜택 관리, 실제 자료와 시연 데이터 구별 |

이 표는 화면 구성 초안이다. 코드 제시·로그인·24시간 기간 계산은 [요구사항](../spec.md#제품-범위)을 따른다.

## 비즈니스 모델

운영 위탁비·판매 수수료는 검토할 재원 후보다. 가맹점 모집, 할인 비용 부담, 사용 내역에 따른 정산 책임, 고객 문의·취소 처리, 서버와 갱신 비용을 확인하기 전 매출이나 지속 가능성을 확정하지 않는다. 과제에서는 사용 이력까지 시연하고 실제 금전 정산은 별도 범위로 검토한다.

## 발전 방향

핵심 발급·사용 검증 이후 실제 제휴와 수요가 확인되면 결제·예약·교통 연계를 검토한다. 첨부 보고서의 정책 사업 확대 계획은 학기 프로젝트 일정과 구분한다.

## 발표 준비

문제·참고 자료→상품·사용 조건→발급·사용 시연→예외·권한 검사→사용성 결과→제휴·운영 한계를 설명한다.
